# 💾 웹 스토리지

> HTTP는 기본적으로 이전 요청의 상태를 기억하지 않기 때문에 쿠키로 상태를 유지해 왔다. 웹 스토리지는 요청에 자동으로 전송하지 않을 클라이언트 데이터를 브라우저에 저장하기 위해 등장했다.

## 정리

### 쿠키의 한계와 웹 스토리지

웹 스토리지를 이해하려면 먼저 쿠키의 한계를 알아야 한다.

쿠키(Cookie)는 설정된 도메인과 경로 조건에 일치하는 HTTP 요청마다 브라우저가 자동으로 서버에 전송한다.
쿠키의 영역에 포함된다면 이미지나 CSS 파일 요청에도 쿠키가 함께 전송될 수 있어 불필요한 트래픽이 발생한다.

또한 저장할 수 있는 용량이 쿠키 하나당 대략 4KB로 작아 많은 데이터를 담기 어렵고, 자바스크립트로 관리하기도 불편하다.
쿠키를 다루는 `document.cookie` API는 다음처럼 여러 옵션을 긴 문자열로 직접 작성해야 하므로 코드를 읽기 어렵고 유지보수도 어렵다.

```js
document.cookie = "doSomethingOnlyOnce=true; Max-Age=86400; SameSite=Lax; Secure";
```

이러한 단점을 보완하기 위해 HTML5와 함께 널리 알려진 클라이언트 저장 방식이 웹 스토리지이다. 웹 스토리지는 쿠키보다 큰 용량을 제공하며, 저장 한도는 브라우저와 사용자 설정에 따라 다르다. 저장된 데이터는 HTTP 요청에 자동으로 포함되지 않는다.

### 웹 스토리지의 종류

웹 스토리지는 데이터를 키-값 형태로 저장한다.

각 값은 고유한 키로 저장하며, 같은 키에 다시 저장하면 기존 값을 덮어쓴다.

웹 스토리지는 데이터의 생명주기에 따라 세션 스토리지와 로컬 스토리지 두 종류가 있다.

- 세션 스토리지: 해당 탭의 페이지 세션 동안 유지되는 임시 저장소
- 로컬 스토리지: 브라우저를 닫아도 명시적으로 삭제하기 전까지 유지되는 저장소

#### 세션 스토리지

세션 스토리지는 해당 탭의 페이지 세션 동안 데이터를 저장하는 임시 저장소이다.
페이지를 새로 고쳐도 데이터는 남아 있지만, 해당 탭을 닫아 페이지 세션이 종료되면 삭제된다.

세션 스토리지는 탭마다 독립된 저장 공간을 가지며, 같은 웹 사이트를 여러 탭에서 열어도 각 탭은 서로 다른 세션 스토리지를 가진다.

세션 스토리지는 잠깐만 유지하면 되는 데이터를 저장하는 데 적합하다. 예를 들어 여러 단계로 구성된 폼에서 사용자가 입력한 내용이나 한 번만 표시하면 되는 알림 팝업 등에 활용할 수 있다.

#### 로컬 스토리지

로컬 스토리지는 사용자 기기에 데이터를 장기간 저장하는 공간이다. 브라우저를 닫았다가 다시 열어도 유지되지만, 코드나 브라우저 설정으로 사이트 데이터를 삭제하면 사라진다.

로컬 스토리지는 프로토콜, 호스트, 포트가 모두 같은 동일 출처 단위로 분리된다. 동일 출처의 탭과 창에서 데이터를 공유하므로, 다크 모드 같은 UI 테마 설정이나 비민감성 장바구니 목록 등에 활용할 수 있다.

### 웹 스토리지 사용하기

```html
<script>
  // 문자열 저장하기
  localStorage.setItem("theme", "dark");
  sessionStorage.setItem("currentStep", "2");

  // 저장된 값 불러오기
  const theme = localStorage.getItem("theme");
  const currentStep = sessionStorage.getItem("currentStep");

  console.log(theme); // "dark"
  console.log(currentStep); // "2"

  // 객체나 배열은 문자열로 변환해 저장하기
  const cart = [
    { id: 1, name: "키보드", quantity: 1 },
    { id: 2, name: "마우스", quantity: 2 },
  ];

  localStorage.setItem("cart", JSON.stringify(cart));

  // 문자열을 다시 객체나 배열로 변환하기
  const savedCart = JSON.parse(localStorage.getItem("cart") ?? "[]");
  console.log(savedCart[0].name); // "키보드"

  // 특정 데이터 삭제하기
  localStorage.removeItem("theme");

  // 해당 스토리지의 모든 데이터 삭제하기
  sessionStorage.clear();
</script>
```

웹 스토리지 API는 매우 직관적이고 간단하다.

웹 스토리지를 사용할 때 `localStorage`와 `sessionStorage`는 같은 메서드를 사용한다. 두 스토리지의 키와 값은 문자열로 저장되므로, 객체나 배열을 저장하려면 `JSON.stringify()`로 문자열로 변환하고 불러올 때는 `JSON.parse()`로 복원해야 한다.

웹 스토리지 API는 메인 스레드에서 동기적으로 동작한다. 따라서 크거나 복잡한 데이터를 자주 읽고 쓰는 용도로는 적합하지 않다. 또한 자바스크립트로 접근할 수 있으므로 인증 토큰과 같은 민감한 정보를 저장하면 안 된다.

### 기타 저장소

웹 스토리지는 간단한 키-값 데이터 저장에 적합하며 더 복잡한 요구사항을 위한 다른 저장소도 존재한다.

- IndexedDB: 대용량 구조화 데이터를 비동기로 저장하고, 색인과 트랜잭션을 사용할 수 있는 브라우저 데이터베이스이다.
- Cache API: 네트워크 요청과 응답을 저장하며, 주로 서비스 워커와 함께 캐시 전략과 오프라인 기능을 구현할 때 사용한다.

## 요약

웹 스토리지는 HTTP 요청에 자동 전송하지 않을 클라이언트 데이터를 동일 출처 단위의 키-값 형태로 저장하는 API이다. 세션 스토리지는 탭의 페이지 세션 동안 유지되고, 로컬 스토리지는 명시적으로 삭제하기 전까지 유지된다. 모든 값은 문자열로 저장되며, 동기적으로 동작하고 자바스크립트로 접근할 수 있으므로 대용량 데이터나 민감한 정보를 저장하는 용도로는 적합하지 않다.
