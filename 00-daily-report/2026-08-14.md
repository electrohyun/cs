# `<iframe>` 태그

> iframe 태그는 웹 개발에서 편의성과 확장성이 크기 때문에 유용하다. 그러나 동시에 문서간 격리 구조, 보안, 성능, 접근성 등 많은 것을 고려해야하는 도구이다.

## 정리

### iframe 태그의 의미와 사용법

iframe은 HTML 문서 안에 또 다른 독립적인 HTML 문서를 삽입하는 태그이다. 쉽게 말하면 웹 사이트 안에 또 다른 웹 브라우저 창을 여는 것과 같다.
웹에서 흔하게 볼 수 있는 예시는 유튜브 영상이나 구글 지도를 웹 사이트에 삽입하는 것이다. iframe 태그 1줄로 외부 서비스를 웹 사이트의 일부처럼 표시할 수 있다.

```html
<iframe
  src="https://youtu.be/embed/abcdef"
  width="815"
  height="815"
  title="임베드영상"
>
</iframe>
```

위는 iframe 태그를 사용해 유튜브 영상 화면을 띄우는 코드이다.

src에 불러온 외부 서비스의 주소를 넣고, width와 height로 표시될 크기를 설정한다. title에는 표시될 화면의 목적을 설명하는 내용을 넣어 스크린 리더 등에서 활용할 수 있게 한다.

### embed, object 태그와 차이점

iframe 태그 이전에도 embed와 object 같은 태그가 외부 콘텐츠를 포함하기 위해 사용되어왔다.

- embed: 가장 오래된 방식으로, 플래시나 PDF 뷰어같은 웹 브라우저 플러그인 기반의 콘텐츠를 삽입하는 데 주로 사용되었다. 표준성과 확장성 면에서 한계가 있는 태그이다.
- object: embed 태그보다 더 널리 사용되며 이미지, 오디오, 비디오, PDF, 다른 HTML 문서등 다양한 종류의 외부 객체를 삽입할 수 있도록 설계되었다. 기능은 강력하지만 단순히 다른 웹 문서를 삽입하는 것이 목적이라면 iframe 태그에 비해 사용법이 다소 복잡하다.

HTML 문서 안에 또 다른 웹 문서를 포함해 보여 주려는 목적이 명확하다면 iframe 태그를 사용하는 것이 가장 직관적이며 표준에 맞는 방식이다.

### iframe 태그의 장단점

장점

- 간편한 외부 콘텐츠 삽입: 유튜브 영상, 지도, 소셜 미디어 피드 등 외부 서비스를 쉽게 웹 사이트에 통합할 수 있다.
- 비동기 로딩: iframe 태그의 내부 콘텐츠는 부모 페이지와 별도로 불러오므로 iframe 태그의 로딩이 느려도 부모 페이지의 렌더링을 막지 않아 초기 로딩 성능에 유리하다.
- 보안 격리: 동일 출처 정책(SOP)에 따라 iframe 태그의 내부 문서와 부모 문서는 서로의 DOM에 직접 접근할 수 없다. 외부 콘텐츠로부터 부모 페이지를 보호하는 중요한 보안장치가 존재한다. (동일 출처 정책이란 한 출처(Origin)에서 로드된 문서나 스크립트가 다른 출처의 리소스와 상호작용하는 것을 제한하는 웹의 핵심 보안 모델이다. 다만 부모 페이지와 iframe 태그가 통신해야 할 때는 이 정책이 장벽이 될 수 있어 이때는 postMessage라는 기술을 사용해 데이터를 안전하게 주고 받는다.)

단점

- 성능 저하: iframe 태그는 DOM이나 window 객체같은 독립적인 브라우저 컨텍스트를 각각 생성한다. 이는 메모리와 cPU 자원을 상당히 소모하므로 페이지 안에 iframe 태그가 많아지면 웹 사이트가 눈에 띄게 느려진다.
- 검색 엔진 최적화의 어려움: 검색 엔진은 iframe 태그 내부 컨텐츠를 부모 페이지와 분리된 콘텐츠로 인식하는 경향이 있다. 이로 인해 콘텐츠가 제대로 색인되지 않거나 ㄱ머색 순위에서 불리하게 작용할 수 있다.
- 보안 취약점: iframe 태그 자체가 취약점은 아니지만 클릭재킹과 같은 공격에서 인터페이스를 겹쳐 속이는 매개체로 악용될 수 있어 신뢰할 수 있는 출처 사용과 서버 보안 헤더 설정이 중요하다. 보안 헤더 설정으로는 iframe 삽입 정책을 제어하는 X-Frame-Options와 iframe 삽입을 허용할 출처를 더 세밀하게 지정할 수 있는 최신 방식인 CSP가 있다. (클릭 재킹이란 악성 사이트 위에 신뢰할 수 있는 사이트를 투명한 프레임으로 겹쳐두고 사용자는 화면에 보이는 버튼을 클릭하면 숨겨진 다른 버튼이 눌리도록 유도하는 공격 기법이다.)

## 요약

> iframe 태그는 HTML 문서 안에 또 다른 독립적인 웹 문서를 삽입할 수 있는 웹 태그로, 유튜브 영상이나 지도 등 욉 ㅜ콘텐츠를 간편하게 통합할 수 있다. 장점으로는 비동기 로딩, 동일 출처 정책에 기반한 보안 격리 등이 있다. 하지만 성능 저하, 검색 엔진 최적화 문제, 클릭재킹과 같은 보안 취약점이 존재한다. 따라서 iframe 태그는 신뢰할 수 있는 콘텐츠에만 사용하고 X-Frame-Options나 CSP 같은 보안 설정을 반드시 적용해야 한다.

- Q1. iframe 태그를 사용했을 때 발생할 수 있는 성능 저하와 검색 엔진 최적화 문제의 원인은 무엇인가요?
- A. iframe은 각 프레임마다 독립적인 브라우징 컨텍스트를 생성해 메모리와 CPU를 추가로 사용하며, 검색 엔진은 내부 콘텐츠를 부모 문서와 분리해 인식하므로 색인과 검색 순위에 불리할 수 있습니다.

- Q2. 클릭재킹 공격을 방지하기 위해 iframe 태그에 적용할 수 있는 보안 설정은 무엇이 있나요?
- A. 서버 응답에 `X-Frame-Options` 또는 CSP의 `frame-ancestors` 지시문을 설정해 허용된 출처만 페이지를 iframe으로 삽입할 수 있도록 제한합니다.
