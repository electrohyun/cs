## 답을 본 뒤 알게 된 것

### HTML의 의미

- 1989년 팀 버너스리가 전 세계 연구자가 정보를 쉽게 공유할 수 있도록 만듬
- 사람들마다 사용하는 문서 형식이 달랐고 호환성 문제 해결하기 위해 만듦

- 콘텐츠를 표시하는 것을 넘어, 정보에 구조와 의미를 부여하는 것을 목표로 함

#### 하이퍼 텍스트

- hypertext
- 특정 단어나 문장에 링크를 부여해 다른 문서나 페이지로 즉시 이동할 수 있게 만든 텍스트
- 웹에서 링크를 클릭해 웹 페이지로 이동하는 모든 행위가 하이퍼텍스트의 원리를 이용하는 것임
  - 원리가 뭔가: 문서 안에 다른 문서의 주소를 참조로 넣어둠. a 태그의 href 값을 현재 문서 기준으로 절대 경로 URL로 해석함. 그 URL로 GET 요청을 보내고, 응답으로 온 HTML을 파싱하고 렌더링... 이후는 같음
- 웹의 가장 큰 특징인 연결성을 구현하는 핵심 개념이다.

#### 마크업 언어

- markup은 표시하다 라는 의미.
- 문서의 구조와 의미를 태그tag라는 약속된 기호를 사용해 표시하는 방식.

- 예를 들어 font-weight라는 스타일은 글자를 굵게 만드는 시각적 효과
- 그러나 < strong > 태그를 사용하면 브라우저에게 "이 단어가 중요한 정보다"라는 의미를 전달할 수 있음.

### HTML의 구조: 태그, 요소, 속성

- HTML 문서는 요소element의 집합으로 이루어지며, 요소는 태그로 표현된다.
- 시작 태그와 종료 태그, 그리고 그 사이의 텍스트까지 합쳐서 요소라고 일컫는다.
- 요소는 화면에 표시할 내용content를 담는 구조.

- 요소에 추가 정보나 기능을 부여할 때는 속성attribute를 사용한다. 속성은 항상 시작 태그 안에 작성하며, 속성명="값"의 형태로 표기.

### HTML의 역할: 정보 구조화와 의미 표시

- HTML이 웹에서 담당하는 역할은 정보의 구조화
- 더 중요한 핵심은 의미를 표시하는 것임. HTML은 글자를 크거나 굵게 보이게 만드는 도구가 아닌, "이건 제목이야", "이건 메뉴 내용이야"라는 역할과 의미를 태그로 알려주는 역할임
- 검색 엔진은 HTML의 태그가 알려준 제목, 본문, 목록 등의 의미로 웹 사이트의 내용을 이해하고 검색 결과를 구성함.
- 또한, 스크린 리더와 같은 접근성 도구도 HTML의 구조적인 의미 정보를 바탕으로 시각 장애인에게 웹 사이트의 콘텐츠를 올바른 순서와 맥락으로 전달함.

### HTML의 진화: 시멘틱과 웹 접근성

- 초기 HTML은 문서의 구조를 표현하는 데 집중
- 웹이 발전하면서 각 요소의 의미를 명확하게 전달하는 것이 중요해짐 -> 시멘틱 HTMLsemantic HTML이 등장함
  - 시맨틱?: semantic, "의미의". -> 태그 이름이 그 안에 든 콘텐츠가 무엇인지 설명한다는 뜻
- 시맨틱 HTML을 실천하는 구체적인 방법: 시맨틱 태그

- 시맨틱 태그는 태그 이름만으로도 해당 영역의 역할을 알 수 있게 해줌.
- div 대신 header
- 본문은 main
- 하단의 저작권 정보는 footer
- 독립된 글은 article, 등등.

- 의미에 맞는 태그를 사용하면 검색 엔진과 스크린 리더도 웹 사이트의 구조를 정확히 이해할 수 있다.
- 이는 검색 엔진 최적화Search Engine Optimization, SEO와 웹 접근성Web Accessibility를 높이는 데 아주 중요함.
- 현재 웹 표준인 HTML5는 이러한 시맨틱 웹 철학을 적극적으로 반영함. header, footer, nav, article, section 등 다양한 시맨틱 태그를 추가해 문서 구조를 더 명확하게 표현할 수 있도록 함.
- 또한 별도의 플러그인 없이도 비디오나 오디오를 재생하는 video, audio, 웹에서 그래픽을 직접 그리는 canvas 등 강력한 기능을 대거 도입 -> 웹의 표현력 높임

### 정리

- HTML, 하이퍼 텍스트 마크업 랭귀지는 웹의 구조를 담당하는 뼈대입니다.
- CSS, 캐스캐이딩 스타일 시트는 디자인을 담당하는 외형입니다.
- JavaScript, 동적 기느을 담당하며 현대적인 웹을 구성합니다.
- HTML은 각 요소의 의미와 구조를 명확하게 표현하여 검색 엔진이나 스크린 리더와 같은 접근성 도구가 내용을 정확히 이해할 수 있게 합니다.
- 그 덕분에 웹 문서가 서로 연결되고 더 잘 검색되며 누구나 접근하기 쉬운 웹 환경이 만들어집니다.
- 단순한 문서 구조를 표현하는 기술로 출발한 HTML은 시맨틱 태그와 HTML5의 등장으로 더 풍부한 기능과 의미 전달을 지원하는 기술로 발전했고, 웹의 핵심 기반으로 자리 잡았습니다.

## 면접용 1분 답변

```
Q1. 웹 개발에서 html, css, 자바스크립트의 역할은 무엇인가요? 건물 짓기에 비유하면 각각 어떤 부분에 해당할까요?
```

- HTML은 문서의 구조와 의미를 정의한다. 어떤 콘텐츠가 어떤 성격으로 존재하는지를 태그로 표현하며, 파싱 결과로 DOM 트리가 만들어진다.
- CSS는 그 구조에 시각적 표현을 입힌다. 선택자로 요소를 지정하고 속성값을 적용하며, 파싱 결과로 CSSOM이 만들어진다.
- 자바스크립트는 동작과 상태 변화를 담당한다. DOM API로 요소를 조작하고 이벤트에 반응하며, 네트워크 요청 같은 비동기 작업을 처리한다.
- 건물에 비유하면 HTML은 골조와 벽, 방 배치에 해당한다. 건물이 어떤 공간으로 구성되는지를 결정한다.
- CSS는 마감재와 도장, 조명에 해당한다. 골조는 그대로 두고 보이는 방식만 바꾼다.
- 자바스크립트는 전기 배선과 엘리베이터, 자동문에 해당한다. 사람의 조작에 반응해 건물이 실제로 동작하게 만든다.
- 셋은 관심사가 분리되어 있어 서로를 바꾸지 않고 각각 교체할 수 있다. 같은 HTML에 다른 CSS를 적용하면 레이아웃만 달라진다.

```
Q2. HTML에서 시맨틱 태그를 사용하는 이유는 무엇인가요? 이것이 검색 엔진 최적화와 웹 접근성에 어떤 도움을 줄까요?
```

- 태그 이름 자체가 콘텐츠의 성격을 설명하므로, 사람과 기계가 동일한 기준으로 문서 구조를 해석할 수 있다.
- `div`에 붙인 클래스명은 개발자 사이의 약속일 뿐이지만, 시맨틱 태그의 의미는 HTML 명세에 정의되어 있어 브라우저와 외부 도구가 공통으로 이해한다.
- 협업과 유지보수 측면에서 마크업만 봐도 문서 구조를 파악할 수 있어 코드 가독성이 높아진다.

(SEO 측면)

- 크롤러가 `article`, `main`, `nav`, `aside`를 구분해 본문과 부가 영역을 판별할 수 있어 색인 품질이 올라간다.
- `h1`부터 `h6`까지의 헤딩 계층이 문서의 목차 역할을 하므로, 검색 엔진이 주제와 하위 주제의 관계를 파악한다.
- `time`, `address` 같은 태그는 값의 종류를 명시해 검색 결과의 리치 스니펫 생성에 활용될 수 있다.

(웹 접근성 측면)

- 브라우저는 DOM으로부터 접근성 트리를 만드는데, 시맨틱 태그는 암묵적 role을 가지므로 보조 기술에 구조가 그대로 전달된다. `nav`는 navigation, `main`은 main role로 매핑된다.
- 스크린 리더 사용자는 이 role을 기준으로 랜드마크 간 이동이나 헤딩 목록 탐색 같은 기능을 쓸 수 있다. 의미 없는 `div` 구조에서는 이런 이동이 불가능하다.
- `button`, `a[href]`, `input` 같은 요소는 기본적으로 포커스를 받고 키보드로 활성화되므로, 마우스를 쓰지 않는 사용자도 조작할 수 있다.
- 같은 동작을 `div`로 구현하면 `role`, `tabindex`, 키보드 이벤트 핸들러를 직접 붙여야 하고, 하나라도 빠지면 접근성이 깨진다.
