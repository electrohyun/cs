## 복습 문제

### Q1

```js
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
```

- **출력: `1 → 4 → 3 → 2`**

동기 실행 단계 (콜 스택)

- `console.log('1')` → 즉시 `1` 출력
- `setTimeout(fn, 0)` → 콜백은 브라우저 타이머 모듈에 등록. 이 시점에 큐에는 아무것도 없음
- `Promise.resolve().then(cb)` → 이미 fulfilled 상태라 `cb`가 그 자리에서 **마이크로태스크 큐**에 진입
- `console.log('4')` → 즉시 `4` 출력
- 전역 코드 끝, 콜 스택 빔

비동기 처리 단계 (이벤트 루프)

- 타이머 만료 → `setTimeout` 콜백이 **태스크 큐**(= 매크로태스크 큐 = 콜백 큐)로 이동
- 콜 스택이 비었으므로 이벤트 루프가 먼저 **마이크로태스크 큐를 전부 비움** → `3` 출력
- 마이크로태스크 큐가 비고 나서야 태스크 큐에서 하나 꺼냄 → `2` 출력

핵심 규칙

- 등록 시점 ≠ 큐 진입 시점 (타이머도, 프로미스도)
- 콜 스택이 비면 → 마이크로태스크 큐 **전부** → 태스크 큐 **하나**
- 그래서 `setTimeout(fn, 0)`은 항상 모든 마이크로태스크보다 뒤

### Q2

```js
setTimeout(() => console.log("A"), 0);
Promise.resolve()
  .then(() => {
    console.log("B");
    Promise.resolve().then(() => console.log("C"));
  })
  .then(() => console.log("D"));
```

- **출력: `B → C → D → A`**

동기 실행 단계 (콜 스택)

- `setTimeout(fn_A, 0)` → 콜백은 브라우저 타이머 모듈에 등록. 큐에는 아무것도 없음
- `Promise.resolve()` → 이미 fulfilled인 프로미스 `p1` 생성
- `p1.then(cb_B)` → `p1`이 fulfilled이므로 `cb_B`가 **즉시 마이크로태스크 큐 진입**. 동시에 새 프로미스 `p2`가 **pending 상태**로 생성됨
- `p2.then(cb_D)` → `p2`가 pending이므로 `cb_D`는 `p2` 내부에 **저장만** 됨. 큐 진입 안 함
- 전역 코드 끝, 콜 스택 빔

큐 상태

```
마이크로태스크 큐: [cb_B]
태스크 큐:         [] → (타이머 만료) → [fn_A]
```

이벤트 루프 1턴차 (마이크로태스크 큐 비우기)

- `cb_B` 실행
  - `console.log('B')` → `B` 출력
  - `Promise.resolve().then(cb_C)` → 이미 fulfilled라 `cb_C`가 **즉시** 큐 진입
  - 콜백 종료 → 반환값 `undefined`로 `p2`가 **fulfilled됨**
  - `p2` 정착 순간, 저장돼 있던 `cb_D`가 큐 진입
- 큐 상태: `[cb_C, cb_D]`
- `cb_C` 실행 → `C` 출력
- `cb_D` 실행 → `D` 출력
- 마이크로태스크 큐 빔

이벤트 루프 2턴차 (태스크 큐)

- `fn_A` 실행 → `A` 출력

핵심 규칙

- `then` 호출은 **새 프로미스를 pending 상태로 생성**한다. 다음 `then`의 콜백은 여기에 저장만 됨
- 앞 콜백이 **종료되면서 반환값으로** 그 프로미스가 정착 → 그때 다음 콜백이 큐 진입
- 그래서 체이닝은 **한 턴에 한 단계씩** 소모됨
- 콜백 **안**에서 등록된 `cb_C`가, 콜백 **종료 후** 등록되는 `cb_D`보다 먼저
- 마이크로태스크 큐가 완전히 빌 때까지 태스크 큐는 열리지 않음 (`A`가 항상 마지막)

### Q3

```js
async function f() {
  console.log("1");
  await g();
  console.log("2");
}
async function g() {
  console.log("3");
}
f();
console.log("4");
Promise.resolve().then(() => console.log("5"));
```

- **출력: `1 → 3 → 4 → 2 → 5`**

핵심 변환 (`await`는 `.then`이다)

```js
// 원본
async function f() {
  console.log("1");
  await g();
  console.log("2");
}

// 사실상 동일
function f() {
  console.log("1");
  return g().then(() => {
    console.log("2");
  });
}
```

- `await` **윗줄** → 동기 실행
- `await` **아랫줄 전부** → 마이크로태스크 (`.then` 콜백과 동일 취급)

동기 실행 단계 (콜 스택)

- `f()` 호출 → async 함수도 `await` 만나기 전까진 보통 함수. 콜 스택 진입
- `console.log('1')` → **`1` 출력**
- `await g()` → `await`는 오른쪽 값을 먼저 구해야 하므로 `g()` **호출**
  - `g` 몸통 실행 → `console.log('3')` → **`3` 출력**
  - `g` 안에 `await` 없음 → 끝까지 동기로 달리고 종료, fulfilled 프로미스 반환
- `await` 작동 → **`f` 중단**. `console.log('2')`가 마이크로태스크 큐 진입. 제어권 전역으로 반환
- `console.log('4')` → **`4` 출력**
- `Promise.resolve().then(cb_5)` → 이미 fulfilled라 `cb_5` 즉시 큐 진입
- 전역 코드 끝, 콜 스택 빔

큐 상태

```
마이크로태스크 큐: [f재개(→2), cb_5]
```

마이크로태스크 처리

- `f재개` → **`2` 출력**
- `cb_5` → **`5` 출력**

핵심 규칙

- async 함수는 호출만으로 미뤄지지 않음. `await`를 만나야 중단됨
- `await`는 **중단점**. 아랫줄은 `.then` 콜백과 같은 취급
- `2`가 `5`보다 먼저인 이유: `await`가 `.then(cb_5)`보다 **윗줄**이라 큐에 먼저 들어감. Q2 규칙 그대로

주의 (면접 대비)

- 2019년 이전 엔진에서는 `await`가 마이크로태스크 큐를 3회 거쳤음 → 그 시절 정답은 `5`가 먼저였음
- V8 7.2 (Chrome 73 / Node 12)에서 1회로 최적화 → 현재는 `2`가 먼저
- 유명한 `async1/async2` 면접 문제 해설 중 옛날 답으로 적힌 게 아직 많음. 실제로 돌려보면 다름

### Q4

```js
Promise.resolve()
  .then(() => {
    return Promise.resolve("X");
  })
  .then((v) => console.log(v));

Promise.resolve()
  .then(() => console.log("1"))
  .then(() => console.log("2"))
  .then(() => console.log("3"));
```

- **출력: `1 → 2 → 3 → X`** (Node v22 실행 확인)

먼저 짚을 것: 프로미스가 두 개다

- `Promise.resolve('X')` — 콜백이 반환한 프로미스. `'X'`를 갖고 있음
- **결과 프로미스** — 첫 번째 `.then()`이 만든 프로미스. `v => console.log(v)`가 붙어 있고 pending 상태
- `'X'`를 앞에서 뒤로 옮겨야 결과 프로미스가 정착하고 `v => console.log(v)`가 큐에 등록됨. 이 옮기는 과정이 큐를 두 번 거친다

실행 흐름

- 전역 코드 실행. 위 체인의 `() => { return Promise.resolve('X'); }`가 마이크로태스크 큐에 등록됨
- 전역 코드 실행. 아래 체인의 `() => console.log('1')`이 마이크로태스크 큐에 등록됨
- 전역 코드 종료. 콜 스택 빔
- 마이크로태스크 큐에서 `() => { return Promise.resolve('X'); }` 수행. 프로미스를 반환했으므로 **반환된 프로미스의 `.then()`을 호출하는 작업**이 마이크로태스크 큐에 등록됨 (반환값이 프로미스인지, 값을 어떻게 꺼내는지는 `.then` 속성을 읽어 호출해봐야 알 수 있어서 실행 중인 콜백 안에서 바로 하지 않고 미룸)
- 마이크로태스크 큐에서 `() => console.log('1')` 수행. `1` 출력. `() => console.log('2')`가 마이크로태스크 큐에 등록됨
- 마이크로태스크 큐에서 `.then()`을 호출하는 작업 수행. `Promise.resolve('X')`는 이미 정착돼 있으므로 **값을 결과 프로미스로 전달하는 콜백**이 마이크로태스크 큐에 등록됨
- 마이크로태스크 큐에서 `() => console.log('2')` 수행. `2` 출력. `() => console.log('3')`이 마이크로태스크 큐에 등록됨
- 마이크로태스크 큐에서 값을 전달하는 콜백 수행. 결과 프로미스가 `'X'`로 정착됨. `v => console.log(v)`가 마이크로태스크 큐에 등록됨
- 마이크로태스크 큐에서 `() => console.log('3')` 수행. `3` 출력
- 마이크로태스크 큐에서 `v => console.log(v)` 수행. `X` 출력

핵심 규칙

- 콜백이 **값**을 반환하면 → 콜백 종료 즉시 결과 프로미스가 정착. 다음 콜백이 바로 큐에 등록됨
- 콜백이 **프로미스**를 반환하면 → `.then()` 호출 작업, 값 전달 콜백. 이 두 단계를 거친 뒤에야 다음 콜백이 등록됨
- 그래서 `X`가 두 칸 밀려 `3` 뒤로 감

```js
.then(() => 'X')                   // 값 반환   → 1 X 2 3
.then(() => Promise.resolve('X'))  // 프로미스  → 1 2 3 X
```

### Q5

```js
const p = new Promise((resolve) => {
  console.log("1");
  resolve("2");
  console.log("3");
});
p.then((v) => console.log(v));
console.log("4");
```

- **출력: `1 → 3 → 4 → 2`**

동기 실행 단계 (콜 스택)

- `new Promise(executor)` 호출. **executor는 그 자리에서 즉시 실행됨**. 큐를 거치지 않음
  - `console.log('1')` → `1` 출력
  - `resolve('2')` → `p`가 `'2'`로 fulfilled 상태가 됨. 이 시점에 `.then`이 아직 안 붙어 있으므로 **큐에는 아무것도 등록되지 않음**
  - `console.log('3')` → `3` 출력. `resolve`는 return이 아니라 상태만 바꾸므로 함수는 계속 실행됨
  - executor 종료
- `p.then(v => console.log(v))` → `p`가 이미 fulfilled이므로 콜백이 **그 자리에서 마이크로태스크 큐에 등록됨**
- `console.log('4')` → `4` 출력
- 전역 코드 종료. 콜 스택 빔

마이크로태스크 처리

- `v => console.log(v)` 수행 → `2` 출력

핵심 규칙

- **비동기 문법이 붙었다고 실행이 미뤄지는 게 아니다. 미뤄지는 건 콜백뿐이다**
  - `new Promise(fn)` → `fn`은 동기
  - `async function` → `await` 만나기 전까진 동기
  - `.then(cb)` → `cb`만 비동기
  - `await` 아랫줄 → 비동기
- `resolve()`는 return이 아님. 상태만 fulfilled로 바꾸고 아래 코드는 계속 실행됨
- 큐 진입 시점 = **정착과 `then` 등록 중 늦은 쪽**
  - Q1: `then`이 먼저 붙고 나중에 정착 → 정착 시점에 큐 진입
  - Q5: 정착이 먼저고 `then`이 나중 → `then` 등록 시점에 큐 진입
