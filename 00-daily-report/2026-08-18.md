# `<h1>`~`<h6>` 헤딩 태그

> 헤딩 태그는 문서의 제목과 섹션 주제를 논리적 구조로 정의하는 역할을 한다.

## 정리

### 헤딩 태그와 헤딩 맵

헤딩 태그는 HTML 문서의 제목과 섹션 구조를 정의하는 태그이다. h1 부터 h6까지 6단계로 구성되며 숫자가 커질수록 더 세부적인 하위 제목을 뜻한다.

정리하자면 이렇다.

```
<h1>: 웹 페이지의 주제를 나타내며 가장 중요하고 유일해야 한다.
<h2>: 웹 페이지의 주요 섹션을 나눈다.
<h3>: 섹션 아래의 하위 주제를 다룬다.
<h4> ~ <h6>: 필요할 때 추가되는 더 세부적인 하위 주제를 나타낸다.
```

헤딩 태그를 올바르게 사용하면 헤딩 맵이라는 논리적인 계층 구조가 만들어진다. 헤딩 맵을 잘 구성하면 다음과 같은 장점이 있다.

- 콘텐츠 분석: 구글, 네이버와 같은 검색 엔진은 헤딩 맵을 분석하여 웹 사이트의 구조와 헤딩 주제를 파악한다. 검색 엔진은 h1 태그에 있는 내용을 웹 페이지의 핵심 주제로 인식하고, h2, h3를 통해 하위 섹션의 세부 주제를 파악하므로 중요한 키워드를 헤딩 태그에 자연스럽게 배치하면 검색 엔진 최적화에 효과적이다.
- 검색 결과 노출: 잘 짜인 헤딩 맵은 검색 엔진이 콘텐츠를 쉽게 이해하도록 도와주므로 검색 결과에서 추천 스니펫과 같은 풍부한 형태로 노출될 확률이 높아진다.

### 헤딩 태그의 사용 규칙

헤딩 태그를 사용할 때는 정보의 계층 구조와 의미를 기준으로 작성해야 하며, 다음 규칙을 지키는 것이 중요하다.

#### 제목 레벨은 순서대로 사용하기

헤딩 태그를 사용할 때 가장 중요한 규칙은 제목 레벨을 건너뛰지 않는 것이다. h1 태그 다음에는 h2, h3 태그 아래에는 h4, h5가 오듯 순차적으로 사용해야 한다.

#### h1 태그는 한 번만 사용하기

h1 태그는 문서 전체를 대표하는 제목으로 하나의 웹 페이지에는 하나의 h1 태그만 사용해야 한다. 시각적으로 글자가 가장 크다는 이유로 페이지에 여러 번 사용하면 검색 엔진 최적화와 웹 접근성 측면에서 문제가 발생한다.

- 검색 엔진 최적화 문제: h1 태그가 여러 개 있으면 검색 엔진이 웹 페이지의 대표 주제가 무엇인지 판단하기 어려워진다. 이는 웹 페이지의 전문성을 떨어트려 검색 엔진 최적화에 악영향을 준다.
- 웹 접근성 문제: 스크린 리더 사용자는 해당 태그를 기준으로 웹 페이지의 구조를 파악하여 원하는 섹션으로 이동한다. h1 태그가 여러 개 있으면 페이지의 개요를 함께 이해하기 어려워져 탐색 과정이 복잡해질 수 있다.

HTML5 명세는 section이나 article 태그 안에서 독립적으로 h1 태그를 사용할 수 있도록 허용한다. 실제 웹 환경에서는 웹 브라우저와 검색 엔진, 스크린 리더와의 호환성을 고려해 웹 페이지당 하나의 h1 태그를 사용하는 것이 가장 안전하고 권장되는 방식이다.

## 요약

> HTML의 헤딩 태그는 HTML 문서의 제목과 섹션 구조를 정의하는 태그로, 문서의 논리적 구조를 정의하는 시맨틱 요소이다. 헤딩 태그를 사용할 때는 올바른 계층 구조를 유지하고 하나의 웹 페이지에는 h1 태그를 하나만 사용하는 것이 검색 엔진 최적화와 웹 접근성에 유리하다.
