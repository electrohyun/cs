# 🌎 웹 표준과 웹 접근성

## 정리

- 건축에 빗대어 표현해보자면...
- 웹 표준은 모든 건물이 따라야 하는 건축법과 설계 규약
- 웹 접근성은 장애인, 노약자 등 누구나 불편 없이 건물을 이용할 수 있도록 경사로와 점자 블록을 설치하는 설계 철학
- 법규만 지킨 건물과 사용 경험까지 고려한 건물은 완성도에서 차이를 느낄 수 있다.

### 웹 표준

- 웹 표준(web standards)는 w3c 같은 공식 표준화 기구가 제정한 웹 기술의 공식 규약이다.
- 쉽게 말해, 웹 사이트를 만들 때 따라야 할 공통 규약을 전 세계가 합의한 것이다.

- 왜 필요한가?
- 어떤 브라우저에서 접속하든 웹 사이트가 동일하게 보이고 정상으로 작동하도록 하는 것이 웹 표준이다.

- 웹 표준을 준수하면 다음과 같은 이점이 있다.
- 호환성 확보: 웹 브라우저별 대응에 드는 개발 비용과 시간을 크게 줄일 수 있다.
- 유지보수 효율 향상: 규칙에 따라 잘 정돈된 코드는 수정과 기능 확장이 쉽다.
- 검색 엔진 최적화: 검색 엔진은 웹 표준을 잘 준수한 웹 사이트의 구조를 더 정확히 이해해 검색 순위 향상에 긍정적인 영향을 준다.

- 가장 기본적인 웹 표준 준수 사례는 시맨틱 태그를 잘 사용하는 것.
- 콘텐츠의 구조와 역할을 태그 자체로 표현하는 것이 웹 표준 준수의 시작점이다.

### 웹 접근성

- 웹 표준이라는 설계도에 따라 건물을 지었다면 이제 누가 이 건물을 사용할 지 정해야 한다.
- 웹 접근성은 사용자의 장애 여부나 이용 환경에 상관없이 누구나 웹 콘텐츠를 똑같이 인식하고 사용할 수 있도록 보장하는 원칙.
- 여기서 핵심은 특정 사용자를 고려하는 게 아닌 모든 사람을 고려한다는 것이 특징.
- 3가지 구체적인 예시로 확인 가능하다.

1. 이미지에 대체 텍스트 제공하기

- 스크린 리더는 화면의 정보를 음성으로 읽어주는 소프트웨어.
- 스크린 리더는 이미지를 만나면 alt 속성에 담긴 텍스트를 읽어준다.
- alt 속성이 비어있다면 사용자는 해당 위치에 어떤 정보가 있는지 전혀 알 수 없다.

2. 키보드만으로 모든 기능에 접근할 수 있도록 하기

- 링크, 버튼, 입력창 등 모든 상호작용 요소는 마우스 없이도 키보드만으로 접근 가능해야 한다.
- 마우스를 사용하지 못하는 사용자 뿐 아니라 키보드를 선호하는 사용자에게도 필수적인 기능.
- div 태그는 마우스로 클릭할 수 있지만, 키보드 포커스를 받을 수는 없습니다.
- 그러나 button 태그는 웹 표준에 따라 키보드 접근이 기본적으로 보장된다.
- 이 차이에서 알 수 있듯, 웹 표준을 지키는 것이 웹 접근성을 지키는 기반이 된다.

3. 충분한 대비 색상 제공하기

- 저시력자나 색각 이상 사용자를 고려해 텍스트와 배경색은 충분히 대비되어야 한다.
- 단순히 예쁘다는 이유로 흰 배경에 연한 회색 글씨를 사용하는 디자인은 가독성을 떨어트려 정보 전달을 방해한다.

### 정리

- 웹 표준은 브라우저의 환경에 상관없이 동일하게 동작하는 웹을 만들기 위한 공식 규약이다.
- 호환성, 유지보수성, 검색 엔진 최적화에 이점을 제공한다.
- 웹 접근성은 모든 사용자가 동등하게 웹을 이용할 수 있도록 보장하는 철학으로, 대체 텍스트 삽입, 키보드 접근성, 색상 대비 확보 등이 핵심 요소.

## 질문

Q1. 웹 표준과 웹 접근성의 차이점과 각각의 목적은 무엇인가요?

- 웹 표준은 W3C, WHATWG, ECMA 등이 정의한 명세(HTML, CSS, DOM, ECMAScript)를 지켜 문서와 코드를 작성하는 것입니다.
  - 목적은 브라우저 구현에 의존하지 않는 상호운용성 확보와 유지보수성, 검색 엔진 대응입니다.
- 웹 접근성은 시각·청각·운동 능력의 제약, 노령, 일시적 상황(밝은 야외, 한 손 사용) 등과 무관하게 모든 사용자가 콘텐츠를 인지하고 조작할 수 있도록 보장하는 것입니다.
  - WCAG의 인식·운용·이해·견고성 네 원칙이 기준이 됩니다.
- 둘의 관계는 포함이 아니라 토대입니다. 시맨틱 마크업, 올바른 폼 레이블, 문서 구조 같은 표준 준수가 접근성의 상당 부분을 자동으로 충족시키지만,
- 키보드 포커스 순서나 색 대비, 동적 콘텐츠 변경 알림은 표준을 지켜도 별도로 설계해야 합니다.
- 접근성 대응은 스크린 리더 사용자만을 위한 것이 아니라 SEO, 자동화 테스트 selector 안정성, 저사양 환경 대응까지 함께 개선합니다.

Q2. 웹 접근성을 높이기 위해 HTML에서 적용할 수 있는 구체적인 방법 3가지는 무엇인가요?

1. 이미지에 대체 텍스트를 작성합니다. 스크린 리더가 이미지를 만나게 될 경우, 스크린 리더 사용자는 이미지 태그의 alt 속성에 적힌 내용으로 정보를 전달받기 때문입니다. 이때 alt는 이미지의 외형 묘사가 아니라 그 자리에서 이미지가 수행하던 역할을 대신하는 텍스트여야 합니다. 링크나 버튼 안의 아이콘이라면 실행되는 동작을 적고, 순수 장식용 이미지는 alt=""로 비워 스크린 리더가 건너뛰도록 합니다. 속성 자체를 생략하면 파일명이 읽히므로 생략과 빈 값은 다릅니다.

2. 키보드만으로 모든 기능에 접근할 수 있도록 합니다. 운동 장애나 손 부상으로 마우스 조작이 어려운 사용자, 스크린 리더 사용자는 키보드에 의존하기 때문입니다. 이를 위해 클릭 가능한 요소는 div가 아닌 button, a 등 시맨틱 태그를 사용해 기본 포커스와 엔터·스페이스 동작을 확보하고, DOM 순서를 시각적 순서와 일치시켜 탭 이동이 자연스럽게 흐르도록 합니다. 포커스 위치가 보이도록 outline을 제거하지 않는 것도 중요합니다.

3. 충분한 대비 색상을 제공합니다. 가령 흰 배경에 회색으로 텍스트를 작성하게 되면 가독성이 떨어져 접근성이 저하됩니다. WCAG는 본문 텍스트에 4.5:1, 큰 텍스트에 3:1 이상의 명도 대비를 요구합니다. 또한 색상만으로 정보를 구분하지 않아야 합니다. 오류 필드를 빨간 테두리로만 표시하면 색각 이상 사용자가 인지할 수 없으므로, 텍스트 메시지나 아이콘을 함께 제공합니다.
