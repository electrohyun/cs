## 답을 본 뒤 알게 된 것

### Doctype의 의미와 역할

- Doctype 선언은 Document Type Declaration, DTD로 웹 브라우저가 HTML 문서를 어떤 버전으로 해석해야 하는지 알려 주는 선언문이다.
- 웹 브라우저는 Doctype 선언을 기준으로 렌더링 모드를 결정한다.
- 렌더링 모드는 표준 모드(standards mode)와 쿼크 모드(quirks mode)로 나뉜다.
  - 표준 모드: W3C나 WHATWG와 같은 웹 표준을 최대한 정확하게 준수하여 렌더링하는 모드로, 평소 알던 것처럼 CSS와 레이아웃이 적용된다. HTML5의 < !Doctype html >은 웹 브라우저를 표준 모드로 동작하게 한다.
  - 쿼크 모드: 오래전에 만들어져 현재의 표준을 따르지 않는 웹 사이트가 최신 웹 브라우저에서도 깨져 보이지 않도록 지원하는 하위 호환성 렌더링 모드이다. Doctype이 선언되지 않거나 잘못 선언되면 웹 브라우저는 문서가 예전 방식으로 만들어졌다고 판단하여 쿼크 모드로 렌더링한다. 이 모드에서는 CSS 해석 방식이 달라져 웹 브라우저마다 결과가 다르게 보이거나 의도와 다르게 레이아웃이 구성될 수도 있다.

> **참고: W3C·WHATWG (웹 표준을 만드는 두 단체)**
> - **W3C** (World Wide Web Consortium): 1994년 웹 창시자 팀 버너스리가 만든 표준화 기구. HTML·CSS·접근성 등 표준을 정한다. 버전을 딱딱 끊어서 냈다(HTML 4.01, XHTML 1.0 …).
> - **WHATWG** (Web Hypertext Application Technology Working Group): 2004년 브라우저 제조사(Apple·Mozilla·Opera, 이후 Google)들이 만든 그룹. W3C의 XHTML 방향이 웹 현실과 동떨어지자 갈라져 나와 **HTML5**를 이끌었다. 버전을 끊지 않고 계속 갱신하는 **Living Standard(살아있는 표준)** 방식이다.
> - **관계**: 한동안 둘이 HTML 표준을 각자 내던 혼란기가 있었으나, **2019년 합의로 이제 HTML·DOM의 공식 표준은 WHATWG의 Living Standard 하나**로 통일됐다. 즉 지금 "표준 모드"가 따르는 표준의 실질적 주인은 WHATWG다.

### Doctype의 과거와 현재

```
‹IDOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN"
http://www.w3.org/TR/html4/loose.dtd">
‹IDOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.1//EN™
"http://www.w3.org/TR/xhtml11/DTD/xhtml11.dtd">
```

- HTML4 시절의 Doctype은 어떤 문서 유형의 정의를 따르는지 명시해야 해서 매우 길고 복잡했다.
- 하지만 HTML5가 표준이 된 현재는 Doctype 선언을 아주 간단하게 표현할 수 있게 되었다.
- 최신 웹 브라우저는 우리가 알고 있던 한 줄 만으로도 HTML5 표준을 따른다는 것을 알고 표준 모드로 렌더링한다.
- Doctype 선언은 웹 브라우저에 '이 문서는 최신 웹 표준을 따르니 표준 모드로 정확하 게 렌더링해야 한다'고 알려 주는 필수 지시어.
- 따라서 웹 개발을 할 때는 문서의 첫 줄에 반드시 < !DOCTYPE html > 선언을 잊지 말아야 한다. 이는 레이아웃과 스타일이 웹 브라우저마다 다르게 보이는 크로스 브라우징 문제를 예방하고 개발자가 의도한 웹 페이지를 만드는 첫걸음이다.

### 정리

- <!DOCTYPE>은 문서가 어떤 HTML 버전을 따르는지 웹 브라우저에 알려주는 선언이다.
- 문서의 가장 첫 줄에 위치해야 한다.
- 웹 브라우저가 이걸 보고 표준 모드로 렌더링 할지, 하위 호환성 렌더링 모드인 쿼크 모드로 렌더링할지 정한다.
- 과거에는 좀 길었지만 HTML5에 오면서 1줄로 줄었고, 이는 크로스 브라우징 문제를 예방하는 핵심 역할을 한다.

### 추가 질문

1. Doctype 선언이 웹 브라우저의 렌더링 모드에 어떤 영향을 미칠까요?

- 웹 브라우저는 표준 모드와 쿼크 모드가 있는데, 표준 모드는 우리가 흔히 아는 그것이고, 쿼크 모드는 현재의 표준을 따르지 않는 옛 사이트가 최신에서 깨져 보이지 않도록 하는 하위 호환성을 위한 모드이다. 이 모드를 결정하는 것이 바로 Doctype 선언이다.

2. 렌더링 모드에는 어떤 것이 있나요? 각각의 모드는 어떤 점이 다른가요?

- 크게 두 가지가 있다. 표준 모드(standards / no-quirks), 쿼크 모드(quirks).
- 표준 모드: `<!DOCTYPE html>`이 있을 때. W3C·WHATWG의 최신 표준대로 렌더링한다. 우리가 평소에 보는 정상적인 결과.
- 쿼크 모드: Doctype이 없거나 잘못됐을 때. 90년대 옛 브라우저(IE5 등) 동작을 흉내 내는 하위 호환 모드다. 대표적인 차이가 **박스 모델**인데, `width`에 padding·border까지 포함해서 계산한다(지금의 `box-sizing: border-box`처럼). 그래서 표준 모드 기준으로 짠 CSS가 크기·레이아웃이 틀어져 보인다.

3. HTML4/XHTML의 Doctype 선면과 HTMLS의 Doctype 선언은 어떤 차이가 있나요?
   Doctype 선언이 HTMLS에서 단순한 형태가 된 이유는 무엇인가요?

- 과거에는 복잡하게 길게 작성해야 했지만, HTML5에 들어와서는 < !DOCTYPE HTML > 만으로 선언할 수 있습니다.
- 짧아진 근본 이유는 **SGML과의 관계가 끊겼기 때문**이다. HTML4·XHTML은 SGML/XML 기반이라 "이 문서는 어떤 DTD(문서 형식 정의)를 따른다"고 그 DTD 파일의 URL까지 적어 줘야 했다. 반면 HTML5는 SGML을 기반으로 하지 않아서 참조할 DTD 자체가 없다.
- 그래서 Doctype에 남은 유일한 실질적 역할은 '브라우저를 표준 모드로 켜는 스위치'뿐이고, 그 역할만 하는 가장 짧은 문자열로 줄어든 것이다. 실제로 `<!DOCTYPE html>`에는 버전 번호조차 없다 — 특정 버전을 가리키는 게 아니라 그냥 "표준 모드로 렌더링해" 라는 트리거일 뿐이다.
